# XCPC 算法模板 by thedyingkai_

这是一个使用 Typst 编写和渲染的 XCPC 算法模板与参考资料项目。

## 比赛检索与章节结构

正文按要解决的问题分类。一级标题为独立领域，二级标题给出功能并保留算法名，三级标题放同一功能的实现和变体；详细推导、边界与反例保留在四级及更深的小节中。

| 一级章节 | 主要入口 |
| --- | --- |
| 数据结构与区间查询 | 并查集、区间统计、第 k 小、离线区间查询、偏序计数、异或查询 |
| 树上问题 | LCA、路径与子树、换根、点分治、虚树、树形 DP、动态森林 |
| 图论 | 最短路、连通性、生成树、逻辑约束、匹配、功能图、基环树 |
| 网络流 | 最大流、最小割、费用流、上下界可行流 |
| 动态规划 | 背包、序列、区间、集合、数位、轮廓、转移优化 |
| 字符串 | 单／多模式匹配、回文、后缀、周期与字典序 |
| 数论 | 同余、逆元、离散对数、整数分解、积性函数与取整求和 |
| 线性代数 | 矩阵运算、快速幂、消元、行列式与逆矩阵 |
| 组合计数 | 组合数、分配、容斥、整数拆分、排列、对称与生成函数 |
| 概率与期望 | 指示变量、尾和、概率分布、自环期望方程 |
| 博弈论 | SG／Nim、反常终止、取石子、循环游戏、得分对抗 |
| 多项式与卷积 | FFT／NTT、集合变换、子集卷积、形式幂级数、求值与插值 |
| 线性递推 | BM 恢复递推、Bostan–Mori 求第 n 项 |
| 计算几何 | 点线、包含、角度、凸包、面积、平移碰撞、格点、距离与反射 |
| 工具与通用技巧 | 整数运算、搜索、排序、调度、构造、对拍工具 |

正文前置“比赛速查”：先按题面信号找功能入口，也可按算法名及常用别名查页码。目录、索引与正文均可点击跳转；页码由各版最终布局自动计算。树形 DP 放在树上问题，概率 DP 放在概率与期望，生成函数建模放在组合计数，其余相关章节提供交叉引用。

文件目录与 PDF 的标题树逐级对应，包括不进入目录页的四、五级说明。一级目录使用一级标题名，子目录使用下一层标题名；每个目录的 `index.typ` 定义本节标题、正文和按顺序导入的子节，对应的 C++ 文件放在本节目录中。Windows 不能用于目录名的半角斜杠统一写成全角 `／`，正文标题同步使用同一写法。

例如，静态区间第 k 小的文件位于 `数据结构与区间查询/区间第 k 小/静态查询：主席树/`，带修改的实现位于同级的 `带修改查询：整体二分/`；LCT 位于 `树上问题/动态森林路径查询（Link-Cut Tree）/`，多项式求逆位于 `多项式与卷积/形式幂级数求逆/`。

`main.typ` 与 `main_plus.typ` 分别配置标准版、紧凑版的排版，共用各目录的正文；`content.typ` 只按顺序汇总一级目录。原来的 Trick 汇总文件已拆到各条目目录，原标签继续用于速查和交叉引用。新增内容时，在对应目录的 `index.typ` 中导入子节，并在 `比赛速查/算法名 → 页码索引/entries.typ` 登记算法名、功能与目标标签即可同时接入两版。`template/` 和 `scripts/` 分别存放排版组件与构建、发布脚本。

## 代码标准与切割

- C++ 板子按 GNU++20 编写。
- 一个文件需要暴露多个可复制部分时，用 `// start: name` 与 `// end: name` 标记完整区段。
- Typst 用 `#code("路径.cpp", parts: ("base", "query"))` 按数组顺序选择并拼接区段。
- 区段名必须唯一且不能嵌套；名称错误、重复引用或标记未闭合会在构建时直接报出文件路径和行号。
- 未使用 `parts` 的旧 `mode` 调用继续兼容；`#include`、`#pragma once` 和标准外层 include guard 默认不进入代码框。

## 计算几何技巧

`计算几何/` 保留 39 个详细条目，以及 2021—2025 年区域赛的 17 道样本题与原题／题解链接。条目按 PDF 标题分布在各功能目录的 `index.typ` 中，平移碰撞、格点构造、距离变换等分别有功能入口。正文按题面信号、推导、适用条件、退化情形、反例与实现整理，关键词速查中可直接跳转。

整数极角、角度归一化、开闭半圆、两种覆盖角宽、原点三角形计数、凸包点定位、有向面积、闵可夫斯基和／差、精确直线交点、最优整点中点构造分别存放在对应条目目录的 C++ 文件中，保留原代码区段标记。`计算几何/几何代码依赖与接口约定/新增代码的依赖、返回值与复杂度/计算几何技巧.cpp` 是汇总 include 入口；各独立文件通过相对路径包含实际依赖。复制片段时注意正文中的依赖和输入约定。

## 本地渲染

渲染当前 `VERSION` 对应的 PDF：

```powershell
.\scripts\render.ps1
```

生成的 PDF 会放在 `dist/` 目录下，该目录不会被提交到仓库。

## 发布版本

小规模改动发布，版本号从 `x.y` 更新为 `x.(y+1)`：

```powershell
.\scripts\release-small.ps1
```

大规模改动发布，版本号从 `x.y` 更新为 `(x+1).0`：

```powershell
.\scripts\release-large.ps1
```

发布脚本会更新 `VERSION`、本地渲染 PDF、提交版本变更、创建 Git tag 并推送到 GitHub。推送 tag 后，GitHub Actions 会自动重新渲染 PDF，并把产物上传到对应的 GitHub Release。

## 版本规则

- `VERSION` 是当前版本号的唯一来源。
- 封面页会自动读取 `VERSION` 并显示为 `vX.Y`。
- 历史 PDF 放在 GitHub Releases 中，`last version/` 目录不会进入版本管理。
